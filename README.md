## 실행

`index.html`을 내려받아 브라우저에서 열거나 위 앱 링크로 접속합니다. 단독 HTML 버전은 별도 설치나 빌드가 필요하지 않습니다.

처음 접속하면 소개 세 장과 초기 설정 두 장을 순서대로 보여줍니다. 설정을 마치면 예시 기록이 없는 덤프에서 시작합니다. 기존 저장 데이터가 있는 사용자는 소개를 다시 강제하지 않고 바로 앱으로 이동합니다.

덤프, 일정, 할 일, 마이의 네 페이지를 제공합니다. 일정과 할 일은 한 줄 목록으로 표시하고, 제목을 누르면 상세 내용을 볼 수 있습니다. 계정 정보에서 두 프로필 시점을 전환해 동작을 확인할 수 있습니다.

## 저장 방식

현재 `index.html`은 **브라우저 localStorage에 데이터를 저장하는 프로토타입**입니다. 실제 서버 로그인, 두 기기 간 계정 연결·동기화, 실제 푸시 알림은 이 HTML에 연결되어 있지 않습니다. 다른 브라우저나 출처(프로토콜·도메인·포트)에서 열면 저장 공간도 달라집니다. 같은 사이트의 `index.html`과 `versions/` 보존본은 앱 저장 키를 공유하며, 별도 체험 HTML만 다른 저장 키를 사용합니다.

사진과 작성 내용을 GitHub에 저장하는 구조는 아닙니다. 이 저장소에는 앱 코드와 명세만 관리합니다. 저장된 개인 데이터가 필요하면 앱의 데이터 설정에서 백업·복원을 사용합니다. 백업 파일은 개인 기록을 포함하므로 공개 저장소에 올리지 않습니다.

## 첫 소개 화면

첫 실행 흐름은 **덤프 피드 소개 → 일정 소개 → 할 일 소개 → 내 정보 → 둘의 정보**입니다.

내 이름은 필수이며 프로필 사진, 상대 이름, 처음 만난 날, 사귀기 시작한 날은 선택입니다. 소개는 실제 제품의 피드·달력·할 일 화면을 중심으로 사용법을 설명합니다. 소개용 예시는 실제 기록에 저장하지 않습니다. 설정 완료 정보와 완료 표식은 같은 앱 데이터에 저장합니다.

마이의 ‘소개 다시 보기’는 사용법 소개 세 장만 보여줍니다. 기존 프로필이나 기록을 초기화하지 않습니다. 첫 실행의 설정 두 장까지 확인하려면 [분리된 체험 HTML](dump-onboarding-preview.html)을 사용합니다. 체험 파일에도 저장된 정보가 있다면 그 체험 데이터로 바로 들어갑니다.

## 리소스와 검수

사용자가 제시한 Retro·BeReal·Howbout 레퍼런스 방향을 참고해 사진 피드를 먼저 보여주고, 일정과 할 일도 실제 제품 화면의 구조로 소개합니다.

소개 사진은 `imagegen` 스킬로 새로 제작한 예시 자산을 JPEG 약 216KB로 압축해 HTML의 data URI로 포함했습니다. 온보딩의 글꼴·로고·소개 사진은 HTML에 내장되어 외부 다운로드 없이 표시됩니다. 브라우저 검수 중 입력한 테스트 이름·게시글·개인 프로필 사진은 별도 QA 주소의 localStorage에서만 사용하며 저장소에 업로드하지 않습니다.

앱 내장 글꼴은 Pretendard 기반 `DumpSans`이며 관련 라이선스 표기를 HTML에 포함합니다. 예시 사진 등 일부 외부 리소스는 인터넷 연결에 영향을 받습니다.

최종 v19 자동 검사 308개와 실제 브라우저 검수는 [v19 검수](docs/QA-v19.md)에 구분해 기록합니다. 실제 브라우저에서는 프로필 사진 파일 선택·압축·미리보기 반영, 정보 완료 후 빈 덤프 진입, 첫 게시 및 다시 보기 후 기록 보존을 확인했습니다. 기존 v18 첫 실행 구현 검수 300개는 [v18 문서](docs/QA-v18.md)에 보존합니다. 기존 한 줄 목록·편집 구조의 v17 검수 이력 228개는 [이전 검수 문서](docs/QA-v17.md)에 보존합니다. 실제 휴대전화, 서버 인증·동기화, 푸시까지 검증한 제품 출시 인증을 의미하지 않습니다.
