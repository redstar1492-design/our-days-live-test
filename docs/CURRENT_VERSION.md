## 첫 실행과 소개 다시 보기

### 첫 실행 다섯 단계

1. 덤프 소개: 실제 사진 피드와 글·댓글 구조를 중심으로 용도 설명
2. 일정 소개: 달력의 기간 막대와 같이하기 구조를 중심으로 용도 설명
3. 할 일 소개: 할 일 목록·D-day·완료 체크 구조를 중심으로 용도 설명
4. 내 정보: 내 이름 필수, 프로필 사진 선택
5. 둘의 정보: 상대 이름, 처음 만난 날, 사귀기 시작한 날을 선택 입력

소개 세 장은 실제 제품 화면을 중심에 두고 짧은 설명으로 연결합니다. 별도의 장식보다 피드·목록·달력의 사용 모습을 먼저 보여주는 방향입니다.

사용자가 제시한 Retro·BeReal·Howbout 레퍼런스 방향을 반영했습니다. 덤프는 사진 피드를 중심에 두고 좋아요·댓글·저장 예시를 제공합니다. 일정은 같이하기·취소와 사진 겹침, 할 일은 완료 체크와 목록 이동을 보여줍니다.

소개 사진은 `imagegen` 스킬로 새로 제작한 예시 JPEG 자산(약 216KB)을 HTML data URI로 내장합니다. 이 이미지는 소개용으로만 사용하며 새 계정의 게시물·프로필에 자동으로 넣지 않습니다. 사용자 개인 사진이나 브라우저 QA 기록은 공개 저장소에 포함하지 않습니다.

- 소개용 피드·일정·할 일은 실제 저장 데이터가 아닌 예시입니다. 앱 데이터에 저장하지 않습니다.
- 소개의 ‘넘기기’는 필수 이름 설정으로 이동합니다. 내 이름을 건너뛰어 빈 프로필로 시작하지 않습니다.
- 내 이름은 1~20자입니다. 상대 이름을 비우면 ‘상대방’으로 표시합니다.
- 사진을 넣지 않으면 중립적인 프로필 자리 표시자를 사용합니다. 예시 인물 사진이나 임의 관계 날짜를 넣지 않습니다.
- 처음 만난 날과 사귀기 시작한 날은 미래 날짜를 선택할 수 없습니다. 두 날짜를 입력했을 때 만난 날이 사귄 날보다 늦으면 저장하지 않습니다.
- 날짜 선택은 앱 안의 공통 글꼴·색상으로 만든 선택창을 사용합니다.
- 완료 시 입력한 프로필·관계 날짜와 소개 완료 표식을 같은 앱 상태에 함께 저장합니다. 중복 클릭을 막고 저장 실패 시 입력을 유지합니다.
- 완료 후 덤프·일정·할 일·알림에 예시 기록을 넣지 않은 상태로 덤프 전체 피드에 진입합니다. ‘덤프 작성’으로 첫 게시를 시작할 수 있습니다.
- 설정 중 다른 창이 데이터를 먼저 저장했다면 새 설정으로 그 데이터를 덮어쓰지 않습니다.

### 기존 사용자와 재체험

- 기존 앱 데이터가 있는 사용자는 v19 업데이트 후에도 바로 기존 앱으로 들어갑니다. 소개 완료 표식이 없는 이전 v17·v18 데이터도 강제로 초기화하거나 첫 설정에 보내지 않습니다.
- 마이의 ‘소개 다시 보기’는 소개 세 장만 보여주고 초기 정보 설정으로 이어지지 않습니다. 닫거나 마지막 단계에서 돌아가도 기존 프로필·날짜·기록은 유지합니다.
- [`dump-onboarding-preview.html`](../dump-onboarding-preview.html)은 본앱과 다른 저장 키를 사용하는 체험 파일입니다. 기존 사용자가 실제 첫 실행의 다섯 단계를 확인할 수 있습니다.
- 체험 파일의 기록은 본앱으로 자동으로 옮기지 않습니다. 체험 파일 자체에도 저장된 정보가 있으면 재접속 시 그 데이터로 바로 들어갑니다.
- 소개 화면은 공통 내장 글꼴, 고정 하단 버튼, 화면 크기에 맞춘 스크롤과 모션 줄이기 설정을 사용합니다.

## 공통 화면

- 기본 탭은 덤프·일정·할 일·마이입니다.
- 상단 `dump` 로고, 페이지별 추가 또는 설정 아이콘, 작성자 기준 필터를 공통으로 사용합니다.
- 덤프·일정·할 일 필터는 전체·나·상대·함께의 같은 구조를 사용하며 나와 상대의 항목에는 설정한 이름을 표시합니다. 내부의 기존 구성원 식별자 ‘준영·아정’은 데이터 호환성을 위해 유지합니다. 저장한 덤프는 별도 저장 목록으로 이동합니다.
- 앱 내장 Pretendard 기반 `DumpSans`를 글자·버튼·입력창·확인창에 사용합니다.
- 좁은 화면에서는 목록을 한 줄로 유지하고 긴 제목을 말줄임합니다. 제목을 누르면 전체 내용을 확인합니다.
- 확인창과 편집창은 앱 내부 UI입니다. 변경 중 닫기에는 ‘계속 작성 / 닫기’를 제공합니다.

## 덤프

- 사진과 글을 게시하고, 장소는 선택 입력합니다.
- 본문과 댓글 버튼은 같은 덤프 상세·댓글 화면으로 이어집니다.
- 사진 순번은 사진 안 우측 하단에 표시합니다.
- 하트·댓글 수·저장 상태를 표시합니다. 저장·저장 취소에는 안내 토스트를 제공합니다.
- 새 게시 후 작성창을 닫고 최상단 피드에 새 카드를 표시합니다. 중복 게시를 막고 이미지 공간을 확보합니다.
- 상대에게 전달되는 댓글 알림을 누르면 해당 덤프·댓글로 이동하고 잠시 하이라이트합니다.
- 저장한 덤프 목록과 내 덤프는 마이에서도 접근할 수 있습니다.

## 일정

### 달력

- 첫 번째 구성원(기존 시연의 준영) 일정은 파란색, 상대 구성원(기존 시연의 아정) 일정은 분홍색 기간 막대로 표시합니다.
- 막대 두께는 모두 6px입니다. 함께하는 일정은 두 사람의 색을 **독립된 두 줄**로 표시합니다. 하나의 줄 안에 두 색을 섞지 않습니다.
- 날짜별 표시 줄은 최대 세 줄입니다. 초과 시 날짜 옆 `+N`으로 숨겨진 색 막대 수를 표시합니다. 함께 일정이 두 줄을 쓰므로 이는 일정 기록 수와 같지 않을 수 있습니다.
- 기간 일정은 주 단위로 같은 줄을 유지합니다. 주·월 경계에서도 실제 기간을 반영합니다.
- 날짜를 누르면 해당 날짜의 모든 일정이 아래 목록에 표시됩니다. 화면에 막대가 생략되어도 일정 자체는 생략되지 않습니다.
- 날짜 칸의 프로필 사진, 색상 이름 범례, 화면에 보이는 기간 드래그 안내 문구는 제거했습니다. 기간 선택 동작은 유지합니다.

### 목록과 참여

- 목록은 **사진 / 제목 / 같이하기·취소 / 메뉴**의 한 줄입니다.
- 목록의 이름·‘등록’·반복 날짜·장소·메모·‘함께’ 문구는 표시하지 않습니다.
- 사진 영역은 항상 46px입니다. 함께할 때 두 사진을 겹치고, 취소하면 남은 참여자 사진 한 장으로 돌아옵니다. 제목 시작 위치와 버튼 영역 너비는 유지합니다.
- 상대 개인 일정의 ‘같이하기’를 누르면 참여자로 추가됩니다. ‘취소’를 누르면 참여를 해제합니다. 원래 작성자는 변경하지 않습니다.
- 제목을 누르면 전체 제목·기간·작성자·장소·메모를 상세창에 표시합니다. 허용된 경우 수정으로 이어집니다.
- 작성·수정 화면에서 작성자는 고정 정보, 참여자는 선택 항목으로 구분합니다. 하루와 여러 날 일정은 시작일·종료일로 설정합니다.
- 선택 날짜의 새로 등록한 일정이 목록 상단에 표시됩니다. 불필요한 ‘종료’ 상태나 수동 완료 동작을 목록에 추가하지 않습니다.

## 할 일

- 목록은 **완료 체크 / 작성자 사진 / 제목 / D-day / 짧은 목표일 / 메뉴**의 한 줄입니다.
- 미래 목표일은 `D-N`, 당일은 `D-day`, 지난 목표일은 `D+N`으로 표시합니다. ‘N일 남음’ 같은 중복 문구를 함께 표시하지 않습니다.
- 목표일 차이는 오늘의 로컬 날짜를 기준으로 일 단위로 계산합니다. 완료한 항목에는 D-day를 표시하지 않습니다.
- 미완료 항목은 당일·가까운 미래 기한부터, 목표일 없는 항목, 기한 지난 항목 순으로 정렬합니다. 완료 항목은 뒤로 보냅니다.
- 제목을 누르면 상세·세부 단계와 전체 날짜를 확인합니다.
- 편집 항목은 작성자·할 일·메모·목표일·함께할 사람·분류입니다. 같은 레이블 열과 밑줄 입력 구조를 사용합니다.
- ‘작성 / 담당’ 문구를 목록에 반복하지 않습니다. 편집의 작성자 정보와 함께할 사람 선택은 별개입니다.
- 분류는 기존 선택 외에 직접 입력을 허용합니다. 1~24자를 저장하고 재로드·백업·수정 후 유지합니다.
- 연결된 일정을 새로 만들 때 목표일이 없다면 일정 시작일을 사용합니다. 기존 준비 기한은 덮어쓰지 않습니다. 사용자가 목표일을 지운 경우 연결 일정에서 다시 채우지 않습니다.

## 마이

- 나의 계정 정보를 중심으로 프로필 사진·편집·커버 사진을 제공합니다. 커버 높이는 260px입니다.
- 관계 정보는 만난 날과 사귄 날을 선택적으로 저장합니다. 미래 날짜와 앞뒤가 맞지 않는 날짜를 검증합니다.
- 내 덤프·저장한 덤프·알림·계정 정보·데이터 설정으로 연결합니다.
- 프로필 편집에서 다른 사람의 프로필 정보를 덮어쓰지 않습니다.
- 시연용 사용자 전환과 데이터 초기화·백업·복원을 제공합니다. 사용자 전환은 실제 서버 로그인 기능이 아닙니다.
- ‘소개 다시 보기’에서 사용법 소개 세 장을 다시 확인할 수 있습니다. 이 동작은 데이터 초기화가 아닙니다.

## 알림과 데이터

- 알림 항목은 덤프·댓글·일정·할 일 등 해당 대상 화면으로 이동합니다. 새 일정 알림도 해당 일정으로 이동합니다.
- 데이터는 현재 브라우저의 localStorage에 저장합니다. 다른 브라우저나 출처(프로토콜·도메인·포트)로 옮기면 같은 데이터가 자동으로 나타나지 않습니다. 같은 GitHub Pages 사이트의 최신 `index.html`과 `versions/` 보존본은 같은 앱 저장 키를 사용합니다.
- 파일 실행 주소와 GitHub Pages 주소는 서로 다른 저장 공간입니다. 필요한 경우 앱의 백업·복원으로 옮깁니다.
- GitHub HTML 업데이트에는 개인 localStorage 기록이나 QA 중 작성한 브라우저 데이터가 들어가지 않습니다.

## 구현 범위 밖

현재 HTML에는 실제 서버 인증·커플 계정 연결·두 기기 동기화·실제 푸시가 연결되지 않았습니다. `next-app/`은 별도 서버 앱 전환 작업이며 이번 명세가 해당 코드의 완성도를 보증하지 않습니다.

첫 실행 정보 입력은 로컬 프로필 설정입니다. 실제 계정 가입이나 상대방의 기기 연결을 완료한 것으로 표시하지 않습니다. 실제 휴대전화에서의 기간 드래그, 키보드, 사진 형식 전체 조합과 보조기기 접근성은 추가 검수가 필요합니다.

검수 증거와 범위는 [v19 검수 내역](QA-v19.md)을 참고합니다. v18 첫 실행 구현은 [v18 문서](QA-v18.md), v17 목록·편집 구조 검수는 [v17 문서](QA-v17.md)에 보존합니다.
