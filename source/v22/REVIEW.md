# v22 독립 제품 검토 및 QA 계획

기준일: 2026-10-10 (Asia/Seoul)  
담당 범위: 사용자 정의서 대응 검토, 신규 자동 검사, 두 차례 검토 결과 정리. 앱 소스·빌드·배포 파일은 root 담당이다.  
현재 단계: 1차 독립 코드 검토·수정과 2차 후보 회귀 검사 완료. 계획 체크 항목은 코드 검사와 실제 브라우저 검수를 구분해 판단한다.

## 사용자 요구와 확인 기준

아래는 root가 전달한 사용자 정의서를 기능별로 나눈 것이다. 사용자의 실제 문구와 기획 해석을 혼동하지 않는다.

## 공통 계약과 리스크

### 1. 네 탭에서 다섯 탭으로

기존 `render()`의 마지막 분기는 알림이다. 톡을 명시적으로 분기하지 않으면 톡 버튼을 눌러 알림 화면이 나올 수 있다. 내부 탭 허용 목록, GNB 5열 배치, 활성 상태, 키보드·스크린리더 이름을 함께 변경해야 한다.

기존 `header('톡')`은 미지원 제목을 할 일 추가 버튼으로 해석한다. 톡 헤더에는 불필요한 +가 나오지 않아야 한다. 공통 `dump` 로고, 헤더 높이, 글꼴·본문 크기·아이콘 크기는 유지한다.

작성 안내는 하단 탭의 위치 번호 대신 `OD.tab('...')` 선택자를 사용하므로 기존 작성 안내의 덤프→일정→할 일→초대 경로를 보존할 수 있다. 톡 체험을 필수 가입 단계로 끼워 넣거나 자동 예시 대화를 생성하지 않는다.

### 2. 피드와 사진은 같은 필터 결과

한 번 필터링한 덤프 목록에서 피드 카드와 사진 목록을 각각 만든다. 모음의 사진이나 첫 사진만 가져오면 요구와 어긋난다. 사진마다 최소 원본 덤프 ID·사진 인덱스·날짜를 유지한다.

- `media`가 있으면 전체 배열을 사용하고, 없는 옛 게시물만 `photoUrl`로 호환한다.
- `media[0]`과 같은 `photoUrl`을 중복 삽입하지 않는다.
- 글만 있는 덤프는 사진 화면에서만 제외한다. 원본은 피드에 남는다.
- 저장한 덤프는 사진별 북마크가 아니라 원본 덤프의 저장 상태를 따른다.
- 작성자/저장 필터를 바꾸어도 피드·사진 모드 선택을 임의로 초기화하지 않는다.
- 날짜 그룹은 한국에서 사용자가 보는 날짜와 일치해야 한다. UTC 자정 근처 ISO 시각을 문자열 앞 10자리로만 자르면 전날로 묶일 수 있다.
- 날짜가 없는 옛 덤프는 안전한 대체 그룹을 사용하고 자동으로 오늘 날짜를 덮어쓰지 않는다.
- 사진을 눌러 원본을 삭제했을 때 빈 사진 화면으로 안전하게 갱신한다.
- 본문·댓글을 닫으면 같은 필터·사진 모드·스크롤 위치를 유지한다.

### 3. 장소 선택은 작성 중인 값과 비동기 응답을 분리

root의 범위 확정: 현재 위치는 실제 첨부하고, 장소명 직접 입력을 보조로 제공한다. 장소 확인은 공통 모달에서 외부 지도 앱/웹 링크를 선택하는 방식이다. 외부 POI 검색 결과나 앱 안 지도 타일·마커 렌더링을 이번 버전에서 구현했다고 표현하지 않는다. 실제 사용자 좌표를 QA 목적으로 가져오지 않고 위치 성공은 fixture를 사용해 검증한다.

기존 `location` 문자열은 읽을 수 있어야 하며, 위치 기능이 없던 게시물을 수정할 때 장소가 지워지지 않아야 한다. 좌표 저장 필드가 추가되면 숫자 범위·문자열 길이·백업 형태를 검증한다.

- 현재 위치 권한은 사용자가 그 버튼을 눌렀을 때만 요청한다.
- 거부·시간 초과·사용 불가·검색 결과 없음·외부 서비스 실패를 성공으로 표시하지 않는다.
- 지도 팝업은 원래 덤프 작성창 위에 열리고, 취소하면 기존 장소·작성 내용·선택 사진이 유지된다.
- 위치 조회 도중 팝업을 닫거나 다른 게시물을 열어도 늦은 응답이 새 작성창에 적용되지 않도록 모달 종류와 세션 토큰을 확인한다.
- 외부 지도 URL에 쓰는 좌표와 첨부한 좌표가 일치한다. 좌표가 없으면 입력한 장소명으로 외부 지도 검색을 연다.
- 현재 위치의 이름 조회가 실패하면 실제 좌표 기반의 위치로 표시하고 근처의 임의 카페 이름을 만들어 붙이지 않는다.
- 장소 이름은 HTML escape하고 외부 지도 링크는 HTTPS와 `noopener noreferrer`를 사용한다.
- 외부 지도는 사용자 클릭으로 열며 앱 내부 지도 로드 성공처럼 표시하지 않는다.
- 빈 이름을 확정하거나 저장한 위치를 제거할 때 문자열과 좌표가 서로 어긋나지 않게 처리한다.

### 4. 톡은 로컬 체험

backend 담당과 합의된 초기 계약:

```text
chatPreview = {
  version: 1,
  exampleLoaded: false,
  exampleReplyIndex: 0,
  messages: []
}
message = {
  id: number,
  sender: 'self' | 'example',
  text: string (1~1000),
  createdAt: ISO,
  read: boolean
}
최대 메시지: 500개
```

기본은 0개 메시지다. `예시 대화 보기` 또는 명시적인 예시 답장 버튼을 누른 경우에만 상대 예시를 추가한다. 자동 답장, 타이핑 중, 전달 완료, 실제 상대의 읽음 표시는 만들지 않는다. 예시 발화자 명칭은 `상대 · 예시`, 안내는 `톡 미리보기 / 메시지는 이 브라우저에만 저장됩니다.`로 실제 범위를 알린다.

제안된 helper: `chatPreviewV22`, `chatUnreadV22`, `chatPageV22`, `chatSendV22`, `chatExamplesV22`, `chatExampleReplyV22`, `chatEnterV22`, `chatRenderAfterV22`.

읽기 accessor와 렌더링은 state를 저장하거나 예시를 만들지 않는다. 저장은 기존 `commit()`을 재사용해 저장 실패·다른 창 충돌 시 입력과 원본을 유지한다. 전송 취소/실패 후 성공 표시를 하지 않는다. 읽음 카운트는 예시 항목의 프런트엔드 상태이며 실제 상대 기기 읽음과 혼동되는 문구를 노출하지 않는다.

### 5. 과거 상태와 복구

v21에서 확인한 경로:

1. `readStoredState()` 검증 실패 → `odStorageIssue` 설정 후 null 반환.
2. `window.state = normalizeState(null)` → 구형 기본 샘플이 메모리에 생성됨.
3. boot는 오류 때문에 빈 상태/소개를 건너뛰고 마지막에 복구창을 표시.

v22에서는 오류 시 원본 raw를 보존하면서 뒤 화면은 빈 복구 상태로 만드는지 확인한다. 원본을 내려받을 수 있어야 하고, 손상 데이터를 자동 덮어쓰기·초기화하지 않는다. ‘샘플로 다시 시작’처럼 새 가입 요구와 다른 복구 동작도 남아 있는지 확인한다.

정상 v17~v21 기록은 기존 데이터이므로 무조건 지우지 않는다. 공개 preview와 로컬 final은 저장 키·origin이 달라 상태가 분리된다는 사실을 검수 보고에 명시하고, 상태 차이를 버전 회귀라고 단정하지 않는다.

## 1차 검토 → 수정 계획

최초 v22 산출 HTML에서 실제 함수와 부트 경로를 실행한다. 신규 테스트는 v21 테스트 숫자를 유지하기 위해 기대 문자열만 억지로 바꾸지 않고, 변경된 요구와 연결 결과를 검증한다.

- [ ] 모든 inline script 구문 검사와 최종 HTML 해시 고정.
- [ ] 실제 render의 5개 GNB 순서·선택·chat 분기 검증.
- [ ] 피드/사진에서 전체·작성자·함께·저장 필터 결과를 원본 ID로 대조.
- [ ] 다중 사진, 옛 photoUrl, 텍스트 전용, 삭제된 원본, 날짜 누락/경계/긴 제목 처리.
- [ ] 사진 클릭의 원본 ID·본문·댓글·복귀 모드 확인.
- [ ] 장소 현재 위치/이름 직접 입력/지도 연결 모달/닫기/지우기/실패/늦은 응답을 검증.
- [ ] 톡 초기0개·수동 예시·한도·빈 입력·중복·HTML 입력·저장 실패/충돌·재접속을 검증.
- [ ] 기존 collections·stops·collectionId와 정상 원본 상태가 보존됨을 대조.
- [ ] 덤프·일정·할 일 작성창에 불필요한 모음 선택 필드가 없음을 확인.
- [ ] 최초 시작·정상 기존 저장·손상 저장·복구 거부 경로에서 데이터 자동 손실/샘플 재생성 없음.
- [ ] 발견한 기능 오류를 root에 전달하고 수정본을 같은 실패 사례로 재검증.

## 2차 검토 → 수정 계획

수정본을 대상으로 신규 검증을 다시 실행하고, 기존 기능 중 구조 변경 영향을 받는 경로의 회귀 검사를 수행한다. root의 실제 브라우저 검수와 코드 검수를 구분해 기록한다.

- [ ] 덤프 작성·수정·본문/댓글·반응·북마크·알림 이동.
- [ ] 일정 기간/달력 막대/같이하기·취소/수정·취소·여행 접근.
- [ ] 할 일 D-day·목표일 순서·체크·하위 항목·할 일→일정 연결·복귀.
- [ ] 마이 프로필·커버·계정·초대 미리보기·사용 안내·백업/복원.
- [ ] 320/390px, 키보드가 열린 낮은 높이, GNB 5개 터치 영역·라벨·입력창 가림.
- [ ] 헤더·본문·입력·날짜·지도 팝업·톡 말풍선·확인창 글꼴과 공통 토큰.
- [ ] 지도/장소 팝업의 ESC·바깥 클릭·닫기·포커스 복귀와 실패 후 재시도.
- [ ] 사진/지도 로드 실패·긴 본문·긴 장소 이름·다수 메시지에서도 가로 넘침 없음.
- [ ] 미연결 새 계정에서 임의 상대 이름·사진·함께 상태·알림이 생성되지 않음.
- [ ] 소스 재빌드 산출물·전달 HTML·배포 HTML의 대응과 최종 해시 확인.
- [ ] 추가 발견 사항 수정 후 관련 검증을 반복하고 최종 결과/남은 한계를 기록.

## 결과 기록 원칙

최종 결과는 `outputs/QA-v22-UI.txt`, `outputs/QA-v22-기존-전체.txt`와 root의 화면 검수 보고에 실제 실행 해시·통과/실패·수정 내역을 기록한다. 모의 DOM 검증을 실기기·실시간 서버 검증으로 표현하지 않는다. 외부 위치 서비스·브라우저 권한·네이티브 시스템 팝업의 확인 범위도 구분한다.

## 1차 검토에서 발견한 수정 사항

1. **여행 상세 → 달력 이동:** `collectionCalendarV21()`이 날짜만 바꾸고 상세 모드를 유지해 달력 대신 여행 상세를 다시 표시했다. root가 이동 전에 상세 모드를 해제하도록 수정했다.
2. **여행 기간 일정의 시작일 버튼:** 모음 선택 필드를 숨긴 뒤 기존 잠금 코드가 상위 `.od-stack`의 첫 버튼을 잘못 비활성화했다. root가 이 잠금 코드를 제거하고 여행 제목 길이 제한을 유지했다.
3. **톡 예시 문구:** 제거된 모음 UI를 안내하는 두 문구가 남아 있었다. 톡 담당자가 현재 화면에서 이해할 수 있는 예시 문구로 교체했다.
